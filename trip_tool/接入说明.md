# 行程规划工具（trip_tool）· 接入说明

> 给组长的版本：一页看完，知道它是什么、怎么接、还差什么。

---

## 一、它是什么

一个**给智能体调用的工具**：输入一个日期，输出当天武汉的景点游览顺序。

```
输入：{"date": "2026-10-25"}          ← 就这一个必填
输出：4 个景点的时间线 + 每段交通耗时 + 排序理由 + 手机导航链接
```

**边界**：它不负责对话、不做天气预测。对话和"把用户口语翻译成参数"由智能体那层做；
它只负责"给定日期和约束，算出一条站得住脚的路线"，结果可复现、可验证。

## 三、算法：一条流水线，不是一个黑盒

| 步 | 做什么 | 关键实现 |
|---|---|---|
| 1 | 取当天 24 小时逐时天气 | Open-Meteo（免费无 key，1 秒）；失败→气候值兜底并打警告 |
| 2 | 筛候选景点 | 半径 / 行政区 / 月份 / 排除项 → 30 个里通常剩 26 个 |
| 3 | **逐时评分** | `score = 100 − Σ(扣分 × 权重)`，扣分：达标 0 / 中间 4 / 不达标 14，权重 0–3。阈值来自数据文件里的模板，**代码里没有气象常识** |
| 4 | **构造时间窗** | 阈值 = `max(60, 当日峰值 − 10)`，取连续达标且最好的一段，与开放时间（含闭馆日 / 停止入场）求交 |
| 5 | **排序求解** | 带时间窗的旅行商问题（TSPTW），OR-Tools 求解：交通时间最短 + 时间窗 + 最多 N 站 + 允许放弃；放弃惩罚 ∝ 适宜度 |
| 6 | 组装 | 每段 km / 分钟 / 交通方式 + 高德深链 + 中文理由 |

- 规模：13 个节点（1 起点 + 12 候选），求解上限 5 秒，实测总耗时 5–9 秒（首次）/ 1–2 秒（有缓存）
- TSPTW 是 NP-hard，用的是启发式（构造初解 + 引导式局部搜索），不保证全局最优，但保证**可行**
- 为什么不用"最近的先去"：多景点 + 时间窗下会死锁（先去了 15:00 才开门的馆，后面全崩）

**诚实说法**：这一步是运筹优化，不是机器学习。它的价值是"把天气翻译成约束"，
让结果可解释、可复现——不会像纯大模型生成那样编造开放时间和距离。

## 四、还差什么才能正式用

### 必须做（不做的直接跑不起来）

| # | 事项 | 谁做 | 估时 |
|---|---|---|---|
| 1 | 安装依赖 `pip install ortools`（不装会退化成贪心，结果能出但差） | 部署的人 | 5 分钟 |
| 2 | 在 `requirements.txt` 加一行 `ortools>=9.8` | 组长/后端 | 1 分钟 |
| 3 | 在 `.gitignore` 加 `data/wuhan/.cache/`（否则缓存文件会进仓库） | 组长/后端 | 1 分钟 |
| 4 | 选一种挂载方式（见第二节），确认 `/api/trip/plan_trip` 返回 200 | 后端 | 10 分钟 |

### 建议做（影响答辩观感）

| # | 事项 | 说明 |
|---|---|---|
| 5 | **正式前端页面** | 现在只有自包含 demo 页（`/api/trip/demo`），风格和你们的 `base.html` 不一致。需要新增一个模板 + JS（不改已有文件，新增即可），把地图换成合规底图（天地图，需免费 key） |
| 6 | 与智能体打通 | 工具定义（`trip_tool/contract.py`）已经写好，但 `services/llm_client.py` 目前是单轮问答、不带 `tools` 参数，需要加 function-calling 循环 |
| 7 | 天气源统一 | 现在用 Open-Meteo；如果要统一到学校给的 CRA40/GOWFS 接口，写一个 provider 用 `hooks.set_weather_provider()` 替换，**不用改工具代码** |
| 8 | 开放时间核实 | 数据校验工具报了 26 条"可信度低"警告，涉及可能按错误时间排 |

### 可选（有余力再做）

- 预取距离矩阵（把常去的 20 个景点两两耗时提前算好落盘）→ 断网也能演示、首屏 1 秒
- 自建 OSRM（Docker）替代公共实例，避免答辩现场被限流
- 公交/地铁方式（现在只有步行 / 打车 / 自动）

cd WeatherAgent-main

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 公共 OSRM 实例限流 / 断网 | 已内置直线距离兜底 + 可预取缓存；重要演示前跑一次预热 |
| Open-Meteo 超出 16 天预报范围 | 自动降级为季节气候值，并在 `warnings` 里说明 |
| 数据文件缺失或格式变化 | 自动降级到内置示例景点，不崩，warning 里写明 |
| 评委问"AI 在哪" | 答：自然语言理解 + 约束抽取 + 结果解释由大模型完成，排序由确定性求解器保证可复现；我们不让模型编造时间与距离 |
