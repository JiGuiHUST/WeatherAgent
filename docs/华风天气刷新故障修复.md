# 华风天气查询/刷新故障修复

修复日期：2026-10-28（北京时间）。

## 已复现的实际故障

修复前对今天、明天、后天和四个常用起点发起 6 次强制天气刷新，全部返回 HTTP 503，提示中国地区来源未确认。网络与 Key 鉴权请求实际成功，错误发生在本项目解析预报时。

一次官方 72 小时响应包含 72 条记录：71 条带 `LocalSource.Id=7`，末尾 `2026-10-31T20:00:00+08:00` 的记录 `LocalSource=null`。旧代码先归一化并校验全部 72 条，再筛选用户选择的日期。因此末尾日期的一条缺失记录会让来源完整的今天、明天和后天一起失败。

这次问题主要在项目对接口边界数据的处理，并非证据表明 Key 无效、配额耗尽或账号没有权限。上一轮验收未覆盖这种跨日期来源缺失组合。

## 修改

1. 先筛选请求的本地日期，再逐条解析和核验来源。未请求日期的数据不会影响本日结果。
2. 保留本日来源核验：本日若有来源缺失或不符合要求的记录，仍返回明确错误，不使用另一小时的来源补齐，不把外源数据标为中国气象局数据。
3. 同一地点和日期的并发刷新合并，在上游缓存有效的前提下，3 秒内的重复刷新复用刚得到的响应。避免图表、规划和重复点击造成重复调用。
4. 查询失败后清除旧温度、雨量、风速、描述和预警状态，避免旧日期的数据留在新错误状态里。
5. 天气源异常增加无密钥日志；来源不明的报错指出具体日期小时，不再直接归因为账号未开通。

## 验证

- 本地回归测试 50 项通过，新增“其他日期缺来源不影响本日”“本日缺来源仍拒绝”“并发刷新只请求一次上游事务”三个用例。
- `tools/check_weathercn_refresh.py` 真实测试 9/9 通过，含今天/明天/后天、四个常用起点与连续刷新，见 `weathercn_refresh_acceptance.json`。
- 今天返回 3 小时剩余预报，明天/后天返回完整 24 小时；不把今天剩余预报补造为全天。
- 关键天气字段和预警权限重新探测通过，见 `weathercn_permission_check.json`。
